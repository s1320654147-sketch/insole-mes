# 鞋垫工厂轻 MES 产品方向

## 当前结论

这套系统不是 ERP，也不是单纯的库存表格。

它应该是一套轻量 MES，核心闭环是：

```text
生产单下发 -> 手机端接单 -> 工序报工 -> 批次库存留痕 -> 看板汇总 -> 异常预警
```

这个方向来自当前工厂诉求，也参考了黑湖小工单视频里的关键做法。

## 5 个战略重点如何落到本项目

### 1. 手机端入口

目标：现场工人不用打开复杂后台，只需要用手机看到自己今天该做什么。

这里的“手机端入口”不是管理后台侧边栏里的一个菜单，而是独立的手机端页面。当前原型已经拆成：

- `prototype/index.html`：管理端，给老板、计划员、仓库和管理人员看
- `prototype/mobile.html`：工人端，给现场工人用手机接任务、看工单、报工和扫码入库

V1 页面：

- 我的待办工序
- 工单详情
- 扫码进入工序
- 快捷报工
- 异常备注

### 2. 工序报工

目标：不是只知道一个生产单是否完成，而是知道每一步做到哪里。

V1 报工字段：

- 生产单
- 工序
- 操作人
- 开始时间
- 完成时间
- 本次完成数量
- 不良数量
- 返工数量
- 异常备注

### 3. 工单界面

目标：管理者和现场人员都能快速知道当前要做什么。

V1 工单界面必须显示：

- 生产单号
- 来源样品单
- 产品名称
- 计划数量
- 已完成数量
- 当前工序
- 交期
- 状态
- 工艺路线

### 4. 看板与报工数据汇总

目标：所有看板都来自真实操作记录，而不是人工再填一遍。

V1 看板：

- 今日重点生产单
- 工序进度
- 缺料风险
- 临期批次
- 延期风险
- 最近操作记录

### 5. 替代纸笔和 Excel

目标：每一次入库、领料、报工、异常、完工都在线留痕。

V1 要替代的纸面记录：

- 打样记录表
- 生产派工单
- 领料单
- 报工表
- 异常登记表
- 库存流水表

## HTML 原型和正式上线的区别

### 当前 HTML 原型

当前 `prototype/index.html` 是一个本地静态原型。

它适合做：

- 快速看页面方向
- 给内部同事讨论
- 和黑湖销售演示时对照提问
- 梳理页面、字段、流程

它不适合直接做：

- 多人同时使用
- 权限登录
- 数据长期保存
- 手机扫码真实报工
- 多人共享实时看板

### 什么时候可以分享

当前 HTML 可以用两种方式分享：

1. 直接把 `prototype` 文件夹发给别人，本地打开 `index.html`
2. 部署到一个静态网站，让大家用链接访问

但是这两种都只是“看原型”，不是正式系统。

### 什么时候需要正式部署

只要进入真实使用，就需要做成在线系统。

正式系统至少需要：

- 前端页面
- 后端接口
- 数据库
- 登录权限
- 数据备份
- 手机端适配
- 内网或公网部署

## 推荐下一步

下一步不要继续扩太多页面，而是把 V1 的真实数据模型定下来。

建议先固定 6 张核心表：

1. 样品单
2. 生产单
3. 工艺路线 / 工序
4. 物料批次
5. 库存流水
6. 报工记录

这 6 张表定住后，再把当前 HTML 原型升级成可录入、可保存、可多人访问的 Web 系统。
