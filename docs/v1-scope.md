# 轻 MES V1 范围

## 业务边界

本系统仅服务于工厂内部生产执行，不承担销售、电商订单、财务结算、集团采购协同等职责。

## 目标

1. 样品和原材料不丢
2. 工单和工序进度可视化
3. 入库、领料、退料、完工、出货留痕
4. 原材料低库存和缺料风险提醒

## V1 模块

1. 样品单
2. 生产工单
3. BOM
4. 工艺路线
5. 物料与库存
6. 报工记录
7. 预警与看板

## 参考基线

这版 V1 的默认思路，主要参考以下成熟产品的共性：

- 黑湖智造：强调生产管理、仓储管理、工艺路线、工厂建模、浏览器使用、开放接口
- ERPNext：用 Work Order + Job Card 拆分工单与工序执行，并支持批次、追溯、在制物料流转
- Odoo：强调 Shop Floor、Work Order、Lot/Expiration/Reordering Rules
- Dolibarr：作为轻量 ERP/制造产品，适合参考小团队的模块收敛方式

结论是：本系统采用“工单驱动 + 工序报工 + 批次库存 + 预警看板”的轻 MES 路线。

## 默认业务决策

### 1. 工单状态默认就按上面这套来

原因：

- ERPNext 的 Work Order / Job Card 是按“工单 -> 工序”分层管理的
- Odoo 的 Shop Floor 也是按工序和工作中心推进
- 对你的小工厂来说，状态过少会看不见问题，状态过多又会增加操作负担

这套状态已经够覆盖：

- 建单
- 备料
- 开工
- 生产
- 暂停
- 质检
- 完工
- 入库

### 2. 原材料必须按批次管理

这个已确定，V1 直接按批次制设计。

批次字段至少包括：

- 批次号
- 来料日期
- 供应商
- 保质期截止日期
- 当前库存
- 当前库位
- 状态：正常 / 临期 / 过期 / 锁定

默认规则：

- 所有库存流水都必须带批次
- 领料优先使用先到期批次
- 临期和过期批次必须预警
- 后续可以加入批次拆分、转库、留样

### 3. 打样单和生产工单分开

这个也已确定。

#### 打样单

适合 10 到 20 双左右

重点关注：

- 版本变化
- 配方/BOM 调整
- 工艺试错
- 客户确认

#### 生产工单

适合已确认样品后的小批量生产，单量最多约 100 双

重点关注：

- 领料
- 工序进度
- 批次消耗
- 完工数量
- 异常与返工

默认关系：

- 一个打样单可以派生多个样品版本
- 一个已确认样品版本可以生成一个或多个生产工单

### 4. 报工按工序，不按整单

V1 默认采用“按工序报工”。

原因：

- ERPNext 的 Job Card 明确按 Operation / Workstation 记录实际执行
- Odoo 的 Shop Floor / Work Order 也是按工序推进
- 你想要“每一步可视化”，按整单报工做不到

但为了现场更轻，交互上可以做两层：

#### 数据模型层

- 按工序报工
- 每条报工记录都挂到工单 + 工序 + 操作人 + 时间 + 完成数量

#### 操作层

- 提供“一键整单完工”快捷入口
- 但系统内部仍然自动补齐为最后一道工序完工

### 5. 生产数量默认支持部分完工

参考 ERPNext 的 Job Card Pending Qty 设计，V1 要支持：

- 本次完成数量
- 剩余待做数量
- 报废数量
- 返工数量

否则小批量生产里很容易因为“今天只做完一半”而把数据做坏。

### 6. 每个工单默认带工艺路线

即使只有 3 到 5 道工序，也必须显式列出来。

鞋垫场景建议初版先支持类似这样的流程模板：

1. 备料
2. 裁切 / 开料
3. 成型 / 压制
4. 修边
5. 检验
6. 包装 / 入库

后续再按真实工艺增删。
