# 小工单官网参考笔记

官网：

- https://www.xiaogongdan.cn/
- https://www.xiaogongdan.cn/products

## 官网强调的主线

黑湖小工单官网的核心表达是：

```text
管生产 + 管物料 + 管绩效
```

对当前鞋垫工厂项目来说，优先参考前两项：

1. 管生产
2. 管物料

`管绩效` 可以先不做，因为当前工人是月薪，不需要计件计时工资。

## 值得借鉴的能力

### 1. 订单履约与生产进度

官网反复强调订单履约、生产进度追踪、工单执行可视化。

本项目对应：

- 生产单
- 工序进度
- 交期
- 延期风险
- 当前状态

### 2. 实时报工

官网提到通过实时报工打破车间黑匣子，让数据实时同步。

本项目对应：

- 工人手机端
- 按工序报工
- 良品数 / 不良数 / 返工数
- 异常备注
- 报工后回流管理端看板

### 3. 物料联动

官网提到物料与生产联动，通过报工自动出入库并实时更新。

本项目对应：

- 批次库存
- 领料
- 退料
- 补料
- 入库
- 库存流水
- 安全库存提醒
- 保质期 / 临期提醒

### 4. 打印模板和二维码

官网提到自定义打印模板、流转单、二维码、扫码报工。

本项目对应：

- 生产单二维码
- 工序二维码
- 物料批次二维码
- 库位二维码
- 手机扫码报工
- 手机扫码入库

### 5. 消息提醒

官网提到逾期、临期、任务、异常、审批、安全库存等提醒。

本项目 V1 建议先做：

- 缺料提醒
- 临期批次提醒
- 延期风险提醒
- 工序暂停 / 异常提醒

审批提醒可以后置。

### 6. 自定义配置

官网提到字段、流程、报表、界面、权限可配置。

本项目 V1 不要一开始做复杂配置系统，但数据库设计要预留扩展：

- 工序可配置
- 物料字段可扩展
- 不良原因可配置
- 用户角色可配置
- 报表筛选可配置

### 7. 多端查看

官网明确覆盖管理层、业务主管、车间现场、一站式运营驾驶舱。

本项目可以拆成：

- 管理端：电脑看板、生产单、库存、预警
- 工人端：手机接任务、看工单、报工、扫码入库
- 后续大屏：车间看板

## 当前项目是否需要调整

当前方向基本正确。

已经覆盖：

- 管理端
- 工人手机端
- 工序报工
- 批次库存
- 预警中心
- 看板汇总

还需要在正式 Web 系统阶段补上：

- 统一数据库
- 登录权限
- 二维码生成和扫码识别
- 后端 API
- 数据保存
- 手机端和管理端数据同步

## 是否马上部署

建议不要马上部署成正式生产系统。

更合适的节奏是：

1. 现在先部署一个内部可访问的 Web Alpha，用来演示和讨论
2. 等黑湖 Demo 体验后，再调整 V1 的字段、状态和扫码细节
3. 再进入正式生产可用版本

原因：

- 当前方向已经明确，可以先做真实 Web 架构
- 但黑湖 Demo 很可能会暴露一些现场交互细节，尤其是扫码、权限、工序流转、库存联动
- 先做 Alpha 不浪费，正式上线前还可以改

## Demo 时重点验证

1. 工人手机端一次报工需要几步
2. 工单二维码和工序二维码怎么生成
3. 扫码后进入的是工单、工序，还是报工表单
4. 物料入库、领料、退料、补料是否都支持扫码
5. 报工是否自动触发出库、入库或库存扣减
6. 管理端看板刷新是实时、准实时，还是手动刷新
7. 权限如何配置，工人能否只看到自己的任务
8. 异常原因和不良原因是否可配置
9. 临期和安全库存提醒在哪里出现
10. 打印模板和二维码标签能否自定义
