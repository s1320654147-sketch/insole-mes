## 视频主线

这段视频的结构非常明确，分成三部分：

1. `Part1 数据收集`
2. `Part2 绩效薪资`
3. `Part3 生产看板`

对当前鞋垫工厂 V1 来说，最值得借鉴的是 `Part1` 和 `Part3`，`Part2` 可以暂时不做。

## 从视频里能看出来的可借鉴点

### 1. 手机端是第一入口

视频里反复出现工人用手机接收任务、查看工单、上报工序数据。

这说明黑湖小工单的核心不是复杂 ERP，而是：

- 先把任务送到人
- 再把现场数据收回来

这和当前项目非常一致。

对我们最值得借鉴的是：

- 手机端工单列表
- 手机端工序报工
- 手机端异常备注
- 手机端查看进度

### 2. 报工颗粒度是“工序级”

视频画面明确出现了类似下面这些信息：

- 进行到哪道工序
- 已完成多少成品
- 由哪位工人生产
- 合格品和不良品
- 不良的原因是什么

这进一步验证：V1 默认应该按工序报工，而不是按整单报工。

### 3. 工单列表是最重要的现场页面

视频中的手机工单页能看到：

- 工单号
- 执行中状态
- 计划数
- 良品数
- 不良品数
- 工序进度

这说明现场一线最需要的不是复杂表单，而是一个能快速判断：

- 现在做哪单
- 做到哪一步
- 做了多少
- 有没有异常

### 4. 看板并不神秘，本质就是报工数据的聚合

视频里能看到：

- 生产总览大屏
- 工单进度趋势
- 不良品分布
- 人员或班组排行

这类“车间智能看板”并不需要一开始就做得很大很重。

对 V1 来说，完全可以先做成三类最小看板：

- 今日进行中的样品单 / 生产单
- 缺料与临期批次预警
- 工序进度与延期风险

### 5. 黑湖把“纸面记录”替换成“留痕数据”

视频里有明显的“使用前”纸笔、Excel、人工抄写画面，也有“使用后”系统留痕画面。

这说明它真正卖的不是某一个功能，而是：

- 所有动作都有记录
- 管理者不用追着人问
- 数据能回到看板上

这非常适合你的诉求：

- 样品和原材料不丢
- 入库、领料、完工、出货留痕
- 每一步可视化

## 当前项目建议借鉴，且优先照着做的能力

### V1 必做

1. 样品单
2. 生产单
3. 批次库存
4. 工序报工
5. 异常备注
6. 缺料 / 临期 / 延期预警
7. 总览看板

### V1.5 可以追加

1. 微信扫码进入工单或工序
2. 班组 / 人员维度统计
3. 不良原因分类
4. 返工记录
5. 简化版车间大屏

### 暂时不做

1. 复杂薪资绩效
2. 复杂财务核算
3. 重型 ERP 模块
4. 过深的设备联网

## 下次和销售沟通时最值得套出来的问题

### 关于工单

1. 他们的工单状态一共有哪几个
2. 工单和工序是什么关系，是不是每个工单都必须挂工艺路线
3. 样品单和生产单是否区分，如果区分，底层对象是不是同一套

### 关于报工

1. 报工是按工序，还是按整单快捷报工
2. 一次报工能不能填写完成数、不良数、返工数、暂停原因
3. 一个工单能不能多人同时报工
4. 报工之后是否自动推进下一工序

### 关于库存

1. 是否支持批次管理
2. 是否支持保质期和临期提醒
3. 领料时是手选批次，还是系统自动推荐先到期批次
4. 退料、补料、报废有没有单独动作

### 关于看板

1. 看板的数据是不是完全来自报工和库存流水
2. 看板默认有哪些指标
3. 延期风险是如何判定的
4. 不良原因统计是怎么录入和汇总的

### 关于移动端

1. 是微信里用，还是独立 App，还是 H5
2. 工人操作是不是只需要 2 到 3 步就能完成报工
3. 有没有扫码直接进入某个工单或工序页面

## 对当前项目的启发

结论很明确：

- 你的方向没有跑偏
- 轻量 MES 比 ERP 更适合这个工厂场景
- 黑湖小工单的真正可借鉴之处，不是它的品牌，而是它把“任务下发 -> 工序报工 -> 数据留痕 -> 看板汇总”做成了一条闭环

我们现在的原型就应该继续沿着这条闭环做。
